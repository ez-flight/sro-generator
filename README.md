# SRO Generator 2.5

Программа создаёт синтетическую модель прямоугольного района съёмки со случайно
расположенными площадными объектами и моделирует досъёмку объектов, недоступных
оптическим системам (например, из-за облачности), средствами РСА ДЗЗ.
Генерируется только геометрия и атрибуты сценария — не радиолокационные
изображения, не орбитальная динамика и не расписание съёмки.

Версия пакета: **2.6.0** (см. CHANGELOG.md, MIGRATION-1.0-TO-1.1.md, BENCHMARK-1.1.md,
CONVERGENCE-ANALYSIS.md, MONTE-CARLO-CONVERGENCE.md, CLOUD-COVERAGE-ANALYSIS.md,
TARGET-OBJECT-DISTRIBUTION.md, TARGET-OBJECT-STATISTICS.md, JOINT-SPATIAL-MODEL.md,
CURVED-LINE-STATISTICS.md).

## Интерфейс (пять вкладок)

**«Генерация СРО»** — настройка района и случайных объектов, воспроизводимая
генерация (seed), визуализация геометрии района, объектов, облачности
(объекты, недоступные оптике, серым со штриховкой) и кадров досъёмки РСА;
отображение рассчитанной геометрической полноты покрытия (оптическое
покрытие, полнота досъёмки скрытых объектов C, итоговая полнота района G).

**«Статистическое исследование»** — оценивание математического ожидания и
дисперсии геометрической полноты покрытия района при досъёмке средствами
РСА ДЗЗ методом статистических испытаний. Пять обязательных графиков:
статистическое математическое ожидание M*(n) с доверительными границами,
исправленная выборочная дисперсия D̃(n), оценка СКО σ̃(n), точность оценивания
ε(β,n) с линией заданной точности ε₀, сходимость алгоритма досъёмки РСА
G(K) и C(K) с доверительными границами и порогами 90/95/99 %. Итоговая
таблица оценок и доверительных интервалов, потребный объём испытаний
n ≥ (z(β)·σ̃/ε₀)² (пилотная нормальная оценка).

**«Модель объектов съёмки»** — математические модели пространственного
распределения целевых объектов ДЗЗ: четыре базовых закона размещения
(равномерно-случайное, групповое/кластерное, регулярное с минимальными
расстояниями, прямолинейное вдоль пространственных структур) и
криволинейное расширение линейного закона — случайная плавная кривая или
импорт линии из GeoJSON (LineString/MultiLineString, WGS 84). Для кривой
настраиваются извилистость (амплитуда бокового изгиба) и ширина коридора;
объекты выбираются равномерно по длине кривой со случайным поперечным
смещением. Доступны визуализация размещения, таблица геометрических
характеристик, экспорт геометрии в GeoJSON и параметров модели в JSON.
Статистическая проверка четырёх базовых законов — стенд
`benchmarks/target_distribution_study.py` (отчёт TARGET-OBJECT-DISTRIBUTION.md):
индекс Кларка–Эванса, квадрантный χ²-критерий, анизотропия направлений,
классические оценки M*(n)/D̃(n)/σ̃(n)/ε(β,n) по N независимым реализациям.

**«Статистическое исследование объектов съёмки»** — экспериментальная
проверка пяти законов пространственного распределения (четыре базовых и
криволинейный) и сходимость статистических оценок (отчёты
TARGET-OBJECT-STATISTICS.md и CURVED-LINE-STATISTICS.md). Одно испытание —
одна независимая реализация распределения; настройка объёма испытаний n,
надёжности β, заданной точности ε₀, закона и характеристики. Шесть
обязательных графиков: реализации законов; эмпирические F*(r) расстояний
до ближайшего соседа с независимым имитационным эталоном и аналитической
кривой Рэлея (CSR); сравнение законов по индексам R, I и R_b с доверительными
границами; сходимость M*(n), D̃(n) и ε(β,n) с линией ε₀ и потребным объёмом
испытаний. Для кривой дополнительно проверяются равномерность вдоль длины
и поперечное отклонение (KS/χ²), а также влияние извилистости на d̄, R, I и
R_b; добавлены таблицы результатов и выгрузки CSV/JSON.

**«Совместная модель района ДЗЗ»** — объединение объектов наблюдения T и
препятствий оптической съёмке B на одном районе с независимыми seed (отчёт
JOINT-SPATIAL-MODEL.md). Объекты T размещаются по любому из пяти законов,
включая криволинейный (случайная плавная кривая или импорт осевой линии из
GeoJSON); препятствия B — поля облачности тем же ядром, перекрытия полей
разрешены.
Точные геометрические операции формируют участки досъёмки РСА U = T ∩ B,
видимую часть T \ B, метрики P_опт = S(T \ B)/S(T) и P_скр = S(T ∩ B)/S(T)
и классификацию объектов (видимые, частично скрытые, полностью скрытые).
Интерактивная карта имеет переключаемые слои района, препятствий, контуров
объектов, видимой части и досъёмки; экспортируются GeoJSON-слои
`district`, `objects`, `obstacles`, `reshoot`, `visible` и JSON-сводка —
вход для дальнейшего планирования в `plane_sar`.

Исследовательские стенды — `benchmarks/convergence_analysis.py` (1.2.0),
`benchmarks/monte_carlo_convergence.py` (1.3.0), `benchmarks/cloud_coverage_analysis.py`
(1.3.0), `benchmarks/target_distribution_study.py` (2.1.0),
`benchmarks/target_statistics_study.py` (2.2.0),
`benchmarks/curved_line_statistics.py` (2.5.0); вычислительные
модули — `sro_generator/convergence.py`, `sro_generator/monte_carlo.py`,
`sro_generator/target_model.py`, `sro_generator/joint_model.py`.

## Установка

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Работа полностью локальная: интернет, API-ключи и картографическая подложка не нужны.

## Запуск

Графический интерфейс (Streamlit):

```bash
streamlit run app.py
```

Пакетная генерация через CLI:

```bash
python -m sro_generator.cli generate --config example_config.json --output output/demo
```

Запуск тестов:

```bash
pytest tests/
```

## Параметры конфигурации (JSON, UTF-8)

### district — район
| Поле | Описание |
|---|---|
| `center_lat`, `center_lon` | Центр района в WGS 84 |
| `width_km`, `height_km` | Размеры района (км; в конфигурации — единицы СИ) |
| `rotation_deg` | Азимут поворота прямоугольника по часовой стрелке от севера; 0 — ориентация по осям |

### objects — объекты
| Поле | Описание |
|---|---|
| `count` | Точное число объектов (не уменьшается программой) |
| `vertices_min`, `vertices_max` | Границы числа вершин, 3…10, выбор равновероятный |
| `area_min_m2`, `area_max_m2` | Диапазон площади (м²), равномерный выбор целевой |
| `irregularity` | Нерегулярность формы 0…1 (0 — правильный многоугольник) |
| `rotation_min_deg`, `rotation_max_deg` | Диапазон случайного поворота объекта |
| `max_aspect_ratio` | Предельное отношение сторон объекта |

### placement — размещение
| Поле | Описание |
|---|---|
| `mode` | Только `"random"` (другие режимы не реализуются) |
| `min_distance_m` | Минимальное расстояние между границами **не пересекающихся** объектов |
| `boundary_margin_m` | Минимальный отступ объектов от границы района |
| `allow_overlap` | Разрешить пересечения по площади |
| `max_overlap_fraction` | Доля попарного перекрытия `area(∩)/min(area)` 0…1 (только при `allow_overlap: true`) |
| `max_attempts_per_object` | Максимум попыток размещения одного объекта |
| `manual_centers` | Список фиксированных центров (см. ниже) |
| `center_region_mode` | `"exact"` (по умолчанию) — точная область центров; `"legacy"` — как в 1.0.0 |
| `spatial_index` | Использовать STRtree для поиска конфликтов (по умолчанию `true`) |

Правила совместимости пар (версия 1.1.0): не пересекающиеся полигоны должны
находиться на расстоянии не менее `min_distance_m`; пересечение по положительной
площади при `allow_overlap: false` запрещено, при `allow_overlap: true` —
допустимо в пределах `max_overlap_fraction`. Касание границ допустимо только
при `min_distance_m = 0`.

### attributes — атрибуты
| Поле | Описание |
|---|---|
| `class_labels` | Категории объектов; каждому объекту назначается случайная |
| `priority_min`, `priority_max` | Диапазон случайного целочисленного приоритета |
| `deadline_choices_h` | Список директивных сроков, выбор случайный |
| `resolution_choices_m` | Список требуемых разрешений, выбор случайный |

### frames — кадры-кандидаты РСА
| Поле | Описание |
|---|---|
| `enabled` | Если `false`, кадры не создаются |
| `along_track_km`, `cross_track_km` | Размеры кадра вдоль и поперёк трассы |
| `pass_azimuths_deg` | Азимуты пролёта (по часовой от севера); на каждый объект и азимут — один кадр с центром в центроиде объекта |

### Верхний уровень
`name` — имя сценария; `seed` — целое число. Одинаковые конфигурация и seed
дают одинаковую геометрию, атрибуты и порядок записей.

## Ручные центры

```json
"manual_centers": [
  {"object_id": "OBJ-001", "latitude": 55.0, "longitude": 60.0}
]
```

Число ручных центров не может превышать `count`, `object_id` должны быть уникальными.
Фиксированные центры не сдвигаются автоматически; остальные объекты размещаются
случайно. В Streamlit таблица ручных центров редактируется прямо на странице.

## Файлы результата (CLI)

- `district.geojson` — граница района (RFC 7946, порядок координат longitude, latitude);
- `objects.geojson` — объекты со всеми атрибутами;
- `objects.csv` — атрибуты без геометрии;
- `frames.geojson` — кадры, если модуль включён;
- `preview.png` — изображение района с объектами и кадрами;
- `config.resolved.json` — фактически использованная конфигурация;
- `generation_report.json` — итоги проверок, число попыток, счётчики STRtree, версия.

## Статистика и аналитика (серия прогонов)

В Streamlit и через `sro_generator.stats`: параллельные серии прогонов со сводными
метриками, статистическими тестами согласия (χ² с p-value и предупреждениями
о применимости, KS для непрерывных распределений, индекс Кларка–Эванса по NND)
и графиками. Сохраняются четыре исходных `chart_*.png` плюс новые в подкаталоге
`analytics/` (распределения, тепловая карта, попытки vs заполнение, χ²/p-value и др.).

## Исследование сходимости алгоритма (1.2.0)

Вкладка «Сходимость алгоритма» в Streamlit и модуль `sro_generator/convergence.py`:
для фиксированного сценария (район, объекты и кадры-кандидаты неизменны, случайность
только в алгоритме) выполняется M независимых экспериментов с seed подряд, каждый —
K итераций рандомизированного жадного отбора кадров РСА. Итерационный алгоритм на
каждом шаге добавляет к объединению выбранных кадров кадр с максимальным приростом
полноты покрытия (softmax-выбор с температурой); полнота информации I(k) —
покрытие района и объектов объединением кадров без повторного счёта перекрытий.
Для каждого эксперимента сохраняется полная траектория I(k); по каждому номеру
итерации считаются среднее, стандартное отклонение, медиана, 10/90-процентили,
95%-й доверительный интервал среднего и средний прирост (данные не сглаживаются).
Диагностика по фактическим результатам фиксирует сходимость, стагнацию, отсутствие
сходимости и сходимость к разным локальным решениям. Регулируются M, K, начальный
seed, критерий стабилизации и минимально требуемая полнота. Экспорт: CSV
(траектории, сводка по итерациям, итоги экспериментов), JSON и четыре PNG
(среднее с полосой p10–p90, std vs k, все траектории, средний прирост).

## Исследование Монте-Карло (1.3.0)

Вкладка «Монте-Карло: средняя полнота» в Streamlit и модуль `sro_generator/monte_carlo.py`:
статистическая сходимость оценки средней геометрической полноты покрытия района при
досъёмке РСА объектов, недоступных оптике (облачность). Каждый из M независимых
запусков генерирует новую случайную конфигурацию объектов СРО из своего seed
(фиксированные район и параметры, одинаковый вычислительный бюджет алгоритма —
K итераций выбора кадров). Оцениваются две метрики: полнота досъёмки скрытых
объектов и итоговая геометрическая полнота района (оптика + РСА, перекрытия без
повторного счёта). По контрольным точкам m (10, 25, 50, 100, 200, 500, 1000)
считаются накопленные среднее, std, SEM и 95%-й ДИ среднего; оценивается число
запусков n* для точности ±1 п.п. при вероятности 95 %. Запланированные кадры —
план наблюдений, а не выполненные съёмки. Досъёмка — жадный отбор с ленивой
очередью (lazy greedy, тот же выбор, что и наивный жадный). Экспорт: CSV
(запуски, контрольные точки), JSON и четыре PNG. Отчёт — MONTE-CARLO-CONVERGENCE.md.

```bash
.venv/bin/python benchmarks/monte_carlo_convergence.py              # M=1000 × K=70
.venv/bin/python benchmarks/monte_carlo_convergence.py --quick      # дымовой прогон
```

## Ограничения

- Единственный режим размещения — случайный; цепочки, коридоры, кластеры,
  регулярные сетки и орбитальный планировщик не реализуются (по постановке задачи).
- Кадр не обязан полностью покрывать большой объект: `coverage_fraction` в
  `frames.geojson` показывает реальную долю покрытия и может быть меньше 1.
- При заведомо неразрешимых ограничениях генерация завершается контролируемой
  ошибкой с указанием `object_id` и рекомендацией (уменьшить площади/число
  объектов, отступы или увеличить район); неполный набор не возвращается как успех.
- Расчёты выполняются в локальной метрической проекции (azimuthal equidistant);
  для районов размером сотни километров это точно, для континентальных масштабов — нет.
