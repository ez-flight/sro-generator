## 1. Что это за проект

Генератор синтетических сценариев района со случайно расположенными объектами
(СРО) для исследований космической радиолокационной съёмки (РСА). Версия
пакета — в `sro_generator/__init__.py`. Карта документации:

- `README.md` — установка, запуск, параметры конфигурации;
- `WIKI.md` — подробный построчный разбор архитектуры;
- `CHANGELOG.md` — история изменений по версиям;
- `MIGRATION-1.0-TO-1.1.md`, `BENCHMARK-1.1.md` — миграция и бенчмарки;
- `CONVERGENCE-ANALYSIS.md` — отчёт об исследовании сходимости алгоритма
  планирования кадров РСА (версия 1.2.0).

## 2. Текущее состояние (на 2026-11-24)

- Версия **1.2.0**, ветка `main` синхронизирована с origin
  (https://github.com/ez-flight/sro-generator). Последний коммит:
  `55da1a7` — исследование сходимости (полностью запушено).
- Модуль `sro_generator/convergence.py`: исследование сходимости
  итерационного алгоритма отбора кадров. Правила выбора кадра:
  `softmax` (температура T), `greedy` (детерминированный), `random`.
  Анализ: `coverage_threshold_analysis` (пороги 90/95/99 % с вероятностью
  ≥ 95 %), `std_trend_analysis` (ρ Спирмена + перестановочный тест),
  `render_comparison_charts`. Экспорт CSV/JSON/PNG.
- Стенд `benchmarks/convergence_analysis.py`: основное исследование,
  температурная сетка T ∈ {0.05, 0.25, 1.0, 4.0}, сравнение алгоритмов.
- Streamlit-приложение `app.py` имеет вкладку «Сходимость алгоритма».
- Тесты: **192 шт., все зелёные** (`.venv/bin/python -m pytest tests -q`).
- Ключевой результат исследования (сценарий 25×25 км, 60 объектов,
  240 кадров, потолок покрытия 0.9967, M=100 × K=200, seeds 0–99):
  итерации достижения порогов с вероятностью ≥ 95 % — 90 % → k=41,
  95 % → k=49, 99 % → k=61; рекомендация **K ≈ 70**; разброс убывает
  статистически значимо (ρ = −0.56, p = 0.0001); T ≤ 0.25; greedy быстрее
  softmax на ~25 %, random — в ~2.8 раза медленнее.

## 3. Оперативные сведения

- Окружение: `.venv` в корне. Запуск UI: `streamlit run app.py`
  (при «Отказано в доступе» на обёртке — `chmod +x .venv/bin/streamlit`
  или `python -m streamlit run app.py`).
- Git-идентичность задана локально: `ez-flight <ez-flight@users.noreply.github.com>`.
- Пуш выполняется токеном GitHub из файла `~/Desktop/token git.txt`
  (одна строка «token git ghp_…»). Пушить только с разрешения пользователя.
  Не встраивайте токен в remote URL и не печатайте его; удобный способ:
  `git -c credential.helper='!f() { test "$1" = get && { echo
  username=x-access-token; echo "password=$(grep -oE "ghp_[A-Za-z0-9]+"
  "$HOME/Desktop/token git.txt")"; }; }; f' push origin main`.
- Сгенерированные артефакты складываются в `output/` (в `.gitignore`).
- Тесты и дымовые прогоны не должны оставлять мусор в репозитории —
  перед коммитом проверяйте `git status`.
