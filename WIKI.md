# WIKI — Генератор района со случайно расположенными объектами (СРО)

Версия пакета: 1.2.0 (`sro_generator/__init__.py`). Дата анализа: 2026-11-23.
Статус анализа: код изучен построчно, тестовый набор `pytest tests/` — 180 тестов, все зелёные.
Изменения 1.0.0 → 1.1.0: см. CHANGELOG.md и MIGRATION-1.0-TO-1.1.md; различия
поведения помечены ниже пометкой «(1.1.0)».

---

## 1. Назначение и контекст

Программа — генератор синтетических сценариев для исследований в области
космической радиолокационной съёмки (РСА). Она строит **сценарий** как набор данных:

1. **Район съёмки** — прямоугольный полигон в WGS 84 с заданным центром, размерами и поворотом.
2. **Площадные объекты** — случайные простые многоугольники (3–10 вершин) с атрибутами:
   категория, приоритет, директивный срок, требуемое разрешение.
3. **Кадры-кандидаты РСА** — прямоугольники съёмки, центрированные на объектах,
   по одному на каждый азимут пролёта, с метрикой покрытия объекта.

Явно **не** генерируется (по постановке задачи): радиолокационные изображения,
орбитальная динамика, расписание съёмки.

Назначение сценариев — воспроизводимые входные данные для downstream-исследований:
планирование съёмки, оценка покрытия, оптимизация по приоритетам, статистические
эксперименты (серии прогонов с разными seed) и верификация генератора самого по себе.

## 2. Общая архитектура

```
config.json ──▶ config.py (pydantic-валидация) ──▶ ScenarioConfig
                                                        │
generator.py: rng = np.random.default_rng(seed)         │
                                                        │
 ├─ geometry.py:  LocalCRS (aeqd) ──▶ полигон района (повёрнутый прямоугольник)
 │
 ├─ placement.py: эрозия района ──▶ ручные центры ──▶ сэмплинг в точной области центров (1.1.0)
 │     ├─ make_shape: углы/радиусы ─▶ контроль aspect ratio ─▶ поворот ─▶ нормировка площади
 │     └─ make_attrs: class / priority / deadline / resolution
 │
 ├─ frames.py: объект × азимут ──▶ кадр в центроиде ──▶ coverage_fraction
 │
 └─ export.py: GeoJSON / CSV / PNG / JSON-отчёты
      (или stats.py: параллельная серия прогонов + χ²-статистики + графики)
```

## 3. Пайплайн генерации (детальный разбор)

### 3.1. Конфигурация и валидация

Вход — JSON (UTF-8) или параметры сайдбара Streamlit. Валидация — pydantic v2
с `model_validator(mode="after")`; любая ошибка — `ConfigError` с именем параметра
и способом исправления. Контролируемые инварианты:

- диапазоны: `vertices_min ≤ vertices_max` (обе в 3…10), `area_min_m2 ≤ area_max_m2`,
  `rotation_min_deg ≤ rotation_max_deg`, `priority_min ≤ priority_max`;
- `max_aspect_ratio > 1`, `irregularity ∈ [0, 1]`;
- ручные центры: уникальные `object_id`, широта/долгота в допустимых пределах,
  число центров ≤ `objects.count`;
- `max_overlap_fraction > 0` допустимо только при `allow_overlap: true`;
- при включённых кадрах нужен хотя бы один азимут пролёта;
- диапазоны центра района: широта ±90°, долгота ±180°.

### 3.2. Локальная метрическая система координат

`LocalCRS` (geometry.py) строит azimuthal equidistant-проекцию:

```
+proj=aeqd +lat_0=<center_lat> +lon_0=<center_lon> +datum=WGS84 +units=m
```

Трансформеры `always_xy`: `to_xy(lon, lat) → (x, y)` (x — восток, y — север, метры)
и обратно `to_lonlat`. **Все** расчёты площадей, расстояний и пересечений выполняются
в локальных метрах, а не в градусах; в WGS 84 геометрия возвращается только на экспорт.
Допустимая точность — районы порядка сотен километров; континентальные масштабы
такой подход не покрывает (см. раздел 8).

### 3.3. Граница района

`build_district_polygon`: прямоугольник `[-w/2, w/2] × [-h/2, h/2]` в метрах,
повёрнутый на `rotation_deg` по часовой стрелке от севера вокруг начала координат
(центр района = центр проекции).

### 3.4. Процедурная генерация формы объекта

Для каждого объекта сначала детерминированно «заказываются» параметры
(все выборки — из общего `rng` сценария):

- `n` — число вершин: равновероятный выбор из `{vertices_min, …, vertices_max}`;
- целевая площадь `A ~ U(area_min_m2, area_max_m2)`;
- угол поворота `rot ~ U(rotation_min_deg, rotation_max_deg)`.

Затем контур строится в четыре приёма (`generate_polygon_shape`):

1. **Углы.** Базовые углы правильного многоугольника `2πi/n` плюс джиттер
   `U(−π/n, π/n) · irregularity`, сортировка по возрастанию — гарантирует простой
   контур с обходом против часовой стрелки. При `irregularity = 0` — правильный
   многоугольник.
2. **Радиусы.** `r_i ~ U(1 − 0.6·irr, 1 + 0.6·irr)`, с ограничением снизу 0.05 —
   форма остаётся звёздно-образной относительно центра (нет самопересечений).
3. **Ограничение отношения сторон.** По `minimum_rotated_rectangle` вычисляются
   стороны `a, b` и `ratio = max/min`. Если `ratio > max_aspect_ratio`, вершины
   проецируются на длинную ось и она сжимается относительно своего центра
   с коэффициентом `max_aspect_ratio / ratio` (< 1); короткая координата сохраняется.
   Число вершин и простота при этом сохраняются.
4. **Поворот и нормировка площади.** Контур поворачивается на `rot`, затем
   равномерно (изотропно) масштабируется относительно центроида с коэффициентом
   `√(A / area)` — площадь становится ровно целевой, aspect ratio не меняется.

Валидация результата: помимо `is_proper_polygon` (полигон валиден и прост,
площадь > 0, число вершин равно заказанному, нет совпадающих соседних вершин
< 1e-9 м) после **всех** преобразований выполняется итоговая проверка
инвариантов (1.1.0): площадь равна целевой с относительным допуском 1e-9,
число вершин не изменилось, отношение сторон `polygon_aspect_ratio` не превышает
`max_aspect_ratio + 1e-6`; при превышении выполняется одна корректирующая
проекция с повторной нормировкой площади, иначе форма отклоняется. Допускается
до 200 повторных попыток построения, иначе — `PlacementError`.
Важно: форма объекта генерируется **один раз** до цикла размещения — при повторных
попытках меняется только положение, не форма и не площадь.

### 3.5. Размещение объектов

`place_objects` выполняет в строгом порядке:

**Подготовка области.** `inner = district.buffer(−boundary_margin_m)` — эрозия
района на величину отступа от границы. Если `inner` пуст — сразу `PlacementError`.

**(1) Ручные центры** (в порядке списка конфигурации). Координаты lat/lon переводятся
в локальные метры; форма строится один раз; проверяется `inner.covers(полигон)` и
дистанционные ограничения против уже размещённых. При нарушении — немедленный
`PlacementError` (центр не сдвигается, форма не подбирается повторно). Режим
`placement_mode = "manual"`, `coordinate_fixed = true`, `attempts = 1`.

**(2) Случайные объекты.** Идентификаторы вида `OBJ-###` (порядковый номер
по мере размещения, после ручных). Для объекта:

- вычисляется **допустимая область центров** (1.1.0): по умолчанию точная
  эрозия области размещения формой объекта — пересечение полуплоскостей
  `n·t ≤ c − max_v(n·v)` по рёбрам выпуклой области `inner` (опорная функция
  линейна, максимум достигается на вершинах контура формы); равномерный выбор
  точки внутри области через веерную триангуляцию от центроида. Режим
  `center_region_mode: "legacy"` повторяет 1.0.0: `region = inner.buffer(−R)`
  (R — описанный радиус) и rejection sampling по ограничивающему прямоугольнику
  с проверкой `region.covers(p)`;
- если область пуста — `PlacementError`;
- для каждой попытки точная проверка конфликтов `pair_placement_ok` (1.1.0,
  семантика ниже) с предварительным отсечением кандидатов: ограничивающий
  прямоугольник кандидата, расширенный на `min_distance_m`, запрашивается у
  `shapely.STRtree` (перестроение каждые 64 объекта; объекты после последнего
  перестроения проверяются линейно по envelope). Отсечение не пропускает
  конфликты: пересечение по площади ⇒ пересечение прямоугольников, расстояние
  < min ⇒ расстояние прямоугольников < min. При `spatial_index: false` — полный
  перебор; решения идентичны (параметризованные тесты эквивалентности);
- попытки суммируются в `report.attempts_total`; при исчерпании лимита — `PlacementError`
  с `object_id` и подсказкой (уменьшить площади/число объектов, отступы или увеличить район).
  **Неполный набор успехом не считается.**

**Семантика `pair_placement_ok` (1.1.0)** — исправление конфликта параметров 1.0.0,
где проверка `distance < min_distance_m` выполнялась первой и блокировала любые
перекрытия, включая разрешённые `max_overlap_fraction`:

- пересечение по положительной площади (`area(∩) > 1e-12·min(area)`):
  `allow_overlap: false` → отказ; `allow_overlap: true` → отказ, если
  `area(∩) / min(area) > max_overlap_fraction`;
- иначе (полигоны не пересекаются, включая касание границ без пересечения
  по площади): `distance ≥ min_distance_m`. Касание допустимо при
  `min_distance_m = 0` и отклоняется при `min_distance_m > 0`.

Сложность (1.1.0): на объект — до N попыток; точных проверок пар при включённом
индексе — O(число кандидатов в окрестности), а не O(все размещённые).

### 3.6. Кадры-кандидаты РСА

`build_frames` — детерминированный шаг (не потребляет RNG): базовый прямоугольник
`cross_track × along_track` сдвигается в центроид объекта и поворачивается на каждый
азимут пролёта. Покрытие: `coverage_fraction = area(obj ∩ frame) / area(obj)`,
с ограничением в [0, 1]. Кадр не обязан полностью покрывать объект (большие объекты
дают значения < 1) и может выходить за границу района — это фиксируется
в предупреждениях, но не считается ошибкой.

### 3.7. Атрибуты

В момент принятия позиции: `class_label ~ choice(class_labels)` (или `None`),
`priority` — целое равномерное, `deadline_h ~ choice`, `resolution_m ~ choice`.
Поскольку атрибуты рисуются после размещения, они зависят от числа совершённых
попыток, но остаются детерминированными при фиксированном seed.

### 3.8. Отчёты и предупреждения

`Scenario.warnings`: число ручных центров, число кадров с частичным покрытием,
предупреждения об откате на legacy-область (невыпуклая область размещения).
`generation_report.json` содержит блок `checks`: точность числа объектов,
валидность всех полигонов, площади в пределах ±1 % от диапазона, вершины в
диапазоне, `coverage_fraction ∈ [0, 1]`; и счётчики 1.1.0: версия пакета,
`placement_exact_checks_total`, `placement_tree_queries`,
`placement_tree_rebuilds`, `center_region_area_mean_m2`.

## 4. Серия прогонов и статистика (stats.py)

`run_batch(config, n_runs, workers, seed_start)`: seeds = `seed_start … + n_runs − 1`,
исполнение в `ProcessPoolExecutor` (или линейно при `workers = 1`);
`run_single` возвращает только plain-данные (без shapely-объектов). Любой сбой
прогона фиксируется как `ok = False` с текстом ошибки — серия не прерывается.

Метрики одного прогона:

- `duration_s`, `attempts_total` (суммарные попытки размещения);
- `exact_checks_total`, `tree_queries`, `tree_rebuilds` — счётчики 1.1.0
  (точные проверки пар, запросы и перестроения STRtree);
- `center_region_area_mean_m2`, `grid_cell_area_fractions` — площадь допустимой
  области центров и доли ячеек сетки 3×3 в ней (для площадной взвески
  ожидаемых частот);
- `fill_ratio = Σ area(объектов) / area(района)`;
- NND (nearest neighbor distance) по центроидам: среднее и минимум, матрица
  попарных расстояний вычисляется векторно через numpy;
- `quadrant_counts` — число центров в ячейках сетки 3×3 над ограничивающим
  прямоугольником района (`QUADRANT_GRID = 3`);
- `coverage` — список `coverage_fraction` по кадрам, `full_coverage_frames`.

Сводка по серии (`summarize`): mean/std/min/max по метрикам; индекс Кларка–Эванса
`clark_evans_r` (описательная метрика: при `min_distance_m > 0` предпосылки CSR
нарушены, что фиксируется в `clark_evans_warnings`); блок `statistical_tests` (1.1.0)
— проверки согласия **с заявленной гипотезой** (не доказательства равномерности):

- `chi2_gof(counts, expected)` — статистика, df, p-value (регуляризованная
  неполная гамма-функция, реализация без внешних зависимостей), предупреждения
  по правилу Кохрана (min expected < 1 — асимптотика недостоверна; доля ячеек
  < 5 > 20 % — грубо). Применяется к числу вершин, категориям, приоритету,
  срокам, разрешениям и сетке 3×3;
- `ks_test(sample, cdf)` — Колмогоров–Смирнов для непрерывных распределений
  (площади против U[area_min, area_max], повороты против U[rot_min, rot_max]);
  `discrete=True` возвращает «неприменим»; при n < 20 и совпадающих значениях —
  предупреждения. Примечание: выборка успешно размещённых объектов может
  отличаться от исходно сгенерированной (отбраковка зависит от площади формы),
  что отражено в предупреждениях теста;
- `quadrant_grid` — χ² по ячейкам 3×3 с ожидаемыми частотами, взвешенными
  площадью пересечения ячеек с допустимой областью центров; для сложных
  гипотез доступен эталонный моделируемый вариант
  (`simulate_reference_quadrant_counts` + `reference_quadrant_counts` в
  `run_batch`/`summarize`).

Совместимость ключей 1.0.0 сохранена: `vertex_chi2_df`, `class_chi2_df`,
`quadrant_chi2_df` (χ²/df) вычисляются из `statistical_tests`.

Выгрузки серии: `runs_summary.csv` (строка на прогон), `objects_all.csv`
(строка на объект, добавлен столбец `aspect_ratio` — для pandas/R),
4 исходных PNG-графика (размещение, атрибуты, геометрия, кадры/пространственная
равномерность) и 10+ новых в подкаталоге `analytics/` (распределения площадей,
вершин, отношения сторон, поворотов, NND; сетка 3×3; тепловая карта центров;
попытки vs заполнение; доля успешных прогонов; сводка χ²/p-value), плюс
`render_series_comparison` для сравнения серий и `render_benchmark_charts`
для таблиц бенчмарка. Реальные измерения, теоретические ожидания и результаты
моделирования на графиках различаются цветом и подписями.

Streamlit оборачивает это в UI с прогресс-баром и вкладками (в т.ч. вкладка
«Аналитика» 1.1.0); результаты серии хранятся в `st.session_state`.

### 4.1. Исследование сходимости итерационного алгоритма (1.2.0)

`convergence.py` исследует не генерацию района, а итерационный алгоритм
формирования кадров РСА — рандомизированный жадный отбор кандидатов. Постановка:
для фиксированного сценария M независимых экспериментов (seed = seed_start …
seed_start + M − 1), каждый — K последовательных итераций. Район, объекты и
кадры-кандидаты генерируются детерминированно из seed сценария в каждом воркере
и неизменны между экспериментами — случайность только в выборе алгоритма;
неизменность контролируется отпечатком сценария (число объектов/кадров, площади,
первая вершина) с фиксацией несовпадений в `warnings`.

Итерация: для каждого оставшегося кадра считается точный прирост полноты при
добавлении к объединению выбранных кадров. Точность достигается поддержкой двух
наращиваемых объединений — пересечений выбранных кадров с районом и с объединением
объектов (∪(кадр ∩ D) = (∪ кадров) ∩ D), поэтому перекрытия кадров не считаются
дважды. Выбор кадра — softmax по приростам с температурой T (вес ∝ exp(Δ/(T·Δmax)):
T → 0 — чисто жадный выбор, T → ∞ — равномерный). Полнота информации
I(k) = 0.5·(S_район + S_объекты), обе компоненты — доли площади, сохраняются
отдельно вместе с id выбранного кадра и приростом; если кадры исчерпаны раньше
K, итерации досчитываются неизменным I(k). Каждый эксперимент возвращает только
plain-данные (без shapely-геометрий), исполнение параллельное и не влияет
на результаты.

`compute_iteration_stats`: по каждому k — среднее, std (ddof=1), медиана,
p10/p90 (линейная интерполяция), 95%-й ДИ среднего (t-критическое уровня 0.975
из встроенной таблицы df = 1…30, далее 1.96; без scipy) и средний прирост
I(k) − I(k−1), I(0) = 0. Данные не сглаживаются.

`ConvergenceParams.selection` задаёт правило выбора кадра на итерации:
`softmax` (взвешенный случайный выбор с температурой T; вес ∝ exp(Δ/(T·Δmax)),
T → 0 — жадный, T → ∞ — равномерный), `greedy` (детерминированный максимум
прироста, RNG не используется — все эксперименты на одном сценарии идентичны)
и `random` (равномерный выбор без ранжирования приростов). Приросты во всех
режимах фиксируются как фактическая разность траектории I(k) − I(k−1).

`coverage_threshold_analysis`: для порога γ (90/95/99 %) доля экспериментов с
I_m(k) ≥ γ по итерациям и минимальное k, где доля ≥ заданной вероятности
(0.95) — итерация достижения порога с требуемой надёжностью; если такого k нет,
порог с данной вероятностью недостижим (фиксируется явно). Доля сопровождается
нормальным 95%-м интервалом.

`std_trend_analysis` проверяет по фактическим результатам, убывает ли разброс
между экспериментами: ρ Спирмена между k и std(k), значимость — перестановочный
тест (фиксированный seed); сходимость заранее не предполагается. Возможен честный
вывод об отсутствии убывания. Константный std (например, детерминированный
greedy) даёт ρ = 0, p = 1.

`diagnose_convergence` проверяет гипотезу о сходимости по фактическим результатам:
стабилизация — с некоторой итерации средний прирост по скользящему окну не
превосходит tolerance до конца K. Вердикты: «converged» (стабилизировалось и
итоговая полнота ≥ min_completeness), «stagnation» (стабилизировалось ниже
требуемого), «different_local_optima» (итоговый std > spread_tol — эксперименты
пришли к разным локальным решениям), «no_convergence». Полоса разброса на
графиках — фактические p10–p90 по экспериментам, искусственное сужение запрещено.

Регулируемые параметры (`ConvergenceParams`): M, K, начальный seed, критерий
стабилизации (порог + окно), минимально требуемая полнота, температура алгоритма,
порог разброса. Экспорт: `convergence_trajectories.csv` (строка на
эксперимент × итерацию), `convergence_summary.csv` (статистика по k),
`convergence_experiments.csv` (итоги), `convergence.json`, четыре PNG
(среднее с полосой p10–p90; std vs k; все траектории I(k); средний прирост vs k).
Streamlit: верхнеуровневая вкладка «Сходимость алгоритма» с тем же сайдбаром
сценария, прогресс-баром, таблицами и кнопками скачивания.

### 4.2. Метод Монте-Карло: сходимость средней полноты (1.3.0)

`monte_carlo.py` исследует не алгоритм, а генератор сценариев: статистическую
сходимость оценки средней геометрической полноты покрытия района при досъёмке
РСА объектов, недоступных оптике (облачность). Постановка: каждый из M
независимых запусков генерирует новую случайную конфигурацию объектов СРО
(seed = seed_start … seed_start + M − 1), параметры района/объектов/кадров и
вычислительный бюджет алгоритма (K итераций выбора кадров) одинаковы. Это
принципиально иная случайность, чем в 4.1: там фиксированный сценарий и
случайный алгоритм, здесь случайные сценарии и (по умолчанию) детерминированный
жадный алгоритм. M (запуски Монте-Карло), K (итерации алгоритма) и число
пролётов КА (`pass_azimuths_deg`) — независимые величины.

Модель оптической недоступности: каждый объект независимо скрыт с вероятностью
`cloud_fraction` (поток RNG привязан к seed запуска — воспроизводимо). Оптическая
съёмка покрывает доступные объекты; скрытые доснимаются РСА. Запланированные
кадры — план наблюдений, а не физически выполненные съёмки; вероятности
реализации плана не моделируются. Метрики запуска: полнота досъёмки скрытых
объектов C (покрытие ∪ кадрами относительно ∪ скрытых объектов) и итоговая
геометрическая полнота района G = area(доступные ∪ (∪ кадров ∩ район)) /
area(района); перекрытия не считаются дважды (два наращиваемых объединения, как
в 4.1). Если скрытых объектов нет, C = NaN и исключается из статистики.

Досъёмка — жадный отбор кадров по приросту комбинированной полноты
0.5·(район + скрытые объекты). Для `greedy` используется ленивая очередь
(lazy greedy): кадр хранится с верхней границей прироста и пересчитывается
только при извлечении; для монотонной субмодулярной функции покрытия выбор
идентичен наивному жадному перебору (тест в `tests/test_monte_carlo.py`), а
число точных пересчётов падает на порядок. `softmax`/`random` перебирают все
оставшиеся кадры на каждой итерации. Нереализуемое размещение объектов
(PlacementError) детерминированно перегенерируется со следующим seed, число
повторов фиксируется.

`compute_running_stats`: по контрольным точкам m (10, 25, 50, 100, 200, 500,
1000) накопленные среднее, std (ddof=1), SEM = s/√m и 95%-й ДИ среднего
(t-критическое). `required_experiments_for_precision`: n* = ⌈(z·s/δ)²⌉ по полной
выборке. `convergence_assessment` проверяет по фактическим данным дрейф среднего
между последними точками (< δ) и убывание неопределённости (наклон ln ДИ от
ln m ≈ −0.5 ± 0.15); убывание std отдельных сценариев не требуется — s стремится
к std генеральной совокупности, а не к нулю. Экспорт: `monte_carlo_experiments.csv`,
`monte_carlo_checkpoints.csv`, `monte_carlo.json`, четыре PNG (панели сходимости
по каждой метрике: среднее±ДИ, std, SEM, полуширина ДИ; гистограммы; сравнение
средних). Streamlit: вкладка «Монте-Карло: средняя полнота». Отчёт —
`MONTE-CARLO-CONVERGENCE.md`.

### 4.3. Сеточный анализ: облачность × K × правило (1.3.0)

`run_cloud_sensitivity` строит сетку «облачность × число итераций K × правило
выбора» поверх того же `run_monte_carlo_experiment`: каждая ячейка — M
независимых запусков, а диапазон seed во всех ячейках одинаков — сценарии
спарены, различия оценок относятся к параметрам ячейки, а не к случайности
сценариев. Задачи пула процессов — отдельные запуски (модульная функция
`_sensitivity_task`, сериализуемая для ProcessPoolExecutor). `compute_combo_stats`:
среднее/std/SEM/95 %-й t-ДИ метрик G и C и доли запусков с метрикой ≥ γ
(90/95/99 %) с нормальным 95 %-м ДИ. `min_k_for_thresholds` — наименьшее K,
где доля ≥ confidence и нижняя граница ДИ ≥ confidence − 0.05.
`verify_cloud_model` проверяет тождество «оптика = объекты − скрытые»,
границы G и C, биномиальность маски облачности (допуск масштабируется как
√(p(1−p)/n)/√M — для малых сценариев шире). Экспорт:
`cloud_sensitivity_summary.csv`, `cloud_sensitivity_thresholds.csv`,
`cloud_coverage.json`, четыре PNG (G(K) и C(K) по облачности для обоих
правил, std vs K, вероятности порогов vs K). Стенд —
`benchmarks/cloud_coverage_analysis.py`. Отчёт — `CLOUD-COVERAGE-ANALYSIS.md`.

## 5. Воспроизводимость и порядок потребления RNG

- Один `rng = np.random.default_rng(seed)` на сценарий создаётся в `generate_scenario`
  и протягивается вниз; потребление строго последовательно:
  параметры формы (n, площадь, поворот) → углы/радиусы → позиции (по попыткам)
  → атрибуты в момент принятия позиции.
- (1.1.0) Сэмплинг позиции потребляет RNG иначе, чем в 1.0.0: выбор треугольника
  веерной триангуляции и две координаты в нём вместо двух координат bbox.
  Поэтому сценарии 1.0.0 не воспроизводятся побайтово; режим `legacy` повторяет
  потребление 1.0.0. STRtree на потребление RNG не влияет (только отсекает
  заведомо неподходящих кандидатов).
- Ручные центры тоже потребляют RNG (на построение формы) — их порядок влияет
  на последующие случайные объекты.
- Кадры RNG не используют: при тех же объектах кадры всегда одинаковы.
- Гарантии закреплены тестами: `test_seed_reproducibility` (побайтовое равенство
  геометрии и атрибутов), `test_different_seed_changes_result`,
  `test_sequential_matches_parallel` (параллельная серия ≡ последовательной).

## 7. Иерархия ошибок

- `ConfigError` — некорректный вход, до начала генерации;
- `PlacementError` — контролируемый отказ размещения (всегда с `object_id`
  и рекомендацией), неполный набор не возвращается;
- в серии прогонов сбой одного прогона — это данные (`ok = False`), а не исключение.

## 8. Ограничения и известные упрощения

1. Единственный режим размещения — случайный; цепочки, коридоры, кластеры,
   сетки и орбитальный планировщик не реализуются (по постановке).
2. Rejection sampling: вероятность принятия зависит от локально свободного места,
   поэтому принятые позиции крупных объектов слегка смещены от краёв района
   (совместное распределение не i.i.d.-равномерно).
3. ~~`region = inner.buffer(−R)` — консервативная оценка~~ — **исправлено в 1.1.0**:
   допустимая область центров вычисляется точно (эрозия Минковского пересечением
   полуплоскостей); режим `legacy` сохраняет старое поведение.
4. ~~Проверка конфликтов — O(n) точных операций на попытку~~ — **исправлено в 1.1.0**:
   STRtree с перестроением каждые 64 объекта и точной финальной проверкой
   кандидатов; решения совпадают с полным перебором.
5. Атрибуты объекта независимы: нет корреляций «категория ↔ площадь ↔ приоритет
   ↔ разрешение», тогда как в реальных сценариях они коррелированы.
6. Кадры — чистая 2D-геометрия: нет угла визирования, наклонной дальности,
   стороны обзора, squint, рельефа; `coverage_fraction` — площадной, а не «видимости».
7. Кадры могут выходить за границу района; статистика таких выходов не ведётся.
8. `fill_ratio` считается по площадям, NND — по центроидам, а не по границам
   полигонов; ячейки 3×3 строятся по ограничивающему прямоугольнику (для
   повёрнутого района это приближение).
9. Район строго прямоугольный; GeoJSON без явного члена CRS (RFC 7946
   подразумевает WGS 84).
10. При `allow_overlap` перекрытие контролируется попарно относительно меньшего
    полигона; суммарной доли перекрытия и транзитивности нет.
11. Ручные центры не устойчивы к конфликтам: форма не подбирается повторно,
    центр не сдвигается — любой конфликт = немедленная ошибка.
12. Локальная СК точна для районов ~сотни километров; континентальные масштабы
    требуют другого подхода.

## 9. Направления дальнейших исследований

### 9.1. Геодезическая точность

- Переключение СК по размеру района: порог, после которого azimuthal equidistant
  заменяется на UTM-зону, сегментированный расчёт или геодезические буферы;
  тесты на антимеридиане, полюсах, экваторе.
- Оценка погрешности метрики (площади, расстояния) как функции размера района
  и широты — количественные допуски вместо качественного «сотни километров точно».

### 9.2. Модели пространственного размещения (стохастическая геометрия)

- Новые режимы размещения: кластерные процессы (Neyman–Scott), коридоры вдоль
  линейной инфраструктуры (граф дорог), регулярные сетки со случайным сбоем,
  стратифицированная выборка; конфигурируемый режим вместо `Literal["random"]`.
- Blue-noise размещение (Poisson disk / алгоритм Bridson) с `min_distance_m`
  как радиусом исключения: убирает rejection sampling, равномерность по построению;
  сравнение с текущим методом по `attempts_total`, χ² и времени.
- Точная эрозия допустимой области формой объекта вместо описанного радиуса
  (разность Минковского) — больше допустимого пространства, меньше ложных отказов.
- Пространственный индекс (shapely `STRtree`) для `_distance_ok`: отсечение
  кандидатов по ограничивающим прямоугольникам до точных проверок.

### 9.3. Реалистичная геометрия РСА

- Модель полосы обзора (swath): угол визирования/наклонной дальности,
  near/far range, ширина полосы, сторона обзора (левый/правый взгляд), squint.
- Покрытие через проекцию местности с эффектами layover/shadowing вместо
  площадного 2D-пересечения.
- Подключение ЦМР (SRTM/Copernicus DEM): высоты объектов, радиотени,
  зависимость видимости от рельефа.
- Полосовые съёмки: stripmap-полосы вдоль азимута, мозаики из нескольких кадров
  для объектов больше одного swath; метрики качества мозаики.
- Синтез обучающих «карточек» РЛИ из геометрии сценария (вплоть до speckle) —
  переход от сценариев к синтетическим изображениям.

### 9.4. Планирование и оптимизация съёмки

Атрибуты уже несут приоритет, срок и разрешение — естественный следующий модуль:

- **Планировщик**: выбор подмножества кадров при ограничениях (время на цель,
  объём данных, директивные сроки, конфликты пролётов).
- Постановки: weighted set cover, ориентирование с временными окнами;
  сравнение жадного алгоритма, MILP (OR-Tools) и метаэвристик на сериях прогонов.
- Метрики планировщика: доля целей, закрытых к дедлайну; суммарный
  priority-weighted coverage; число перенацеливаний.
- Мультиспутниковый сценарий: несколько КА, упрощённые орбитальные параметры,
  конфликты по станциям сброса данных.

### 9.5. Статистическая верификация генератора

- Тесты точечных процессов: Ripley K/L, Clark–Evans, Morisita index;
  критерии согласия распределений (KS против U[area_min, area_max] и дискретных
  равномерных распределений приоритетов/сроков).
- χ² с порогами значимости и p-value (сейчас — только статистика без решения).
- Чувствительность: профили `attempts_total` и доли отказов как функции
  `irregularity`, `max_aspect_ratio`, плотности заполнения; карта «границы
  разрешимости» конфигураций.
- A/B-сравнение конфигураций через batch-инфраструктуру: общие случайные числа
  (common random numbers) для снижения дисперсии сравнения.

### 9.6. Производительность и масштаб

- Профилирование hot path; кэширование bounding box и их отсечение до точных
  операций; векторизация `_distance_ok`.
- NND через KD-tree (scipy) при больших count — убрать O(n²) по памяти.
- Целевой масштаб: 10⁴–10⁵ объектов; оценка роста времени и попыток,
  регрессионные тесты производительности.
- Потоковый экспорт больших GeoJSON; альтернативные форматы (GeoPackage,
  FlatGeobuf) с явным CRS.

### 9.7. Реализм сценариев и внешние данные

- Импорт реальных контуров зданий/сооружений (OpenStreetMap) как альтернатива
  процедурным полигонам.
- Привязка категорий к землепокрытию (CORINE/GlobCover); правила корреляции
  атрибутов (например, «warehouse → крупная площадь, высокий приоритет»).

## 11. Термины

- **РСА** — радиолокатор с синтезированной апертурой (SAR).
- **СРО** — район со случайно расположенными объектами.
- **aeqd** — azimuthal equidistant, азимутальная равнопромежуточная проекция.
- **NND** — nearest neighbor distance, расстояние до ближайшего соседа.
- **fill_ratio** — доля площади района, занятой объектами.
- **coverage_fraction** — доля площади объекта, попадающая в кадр.
- **Rejection sampling** — метод отбора точек с отказом (проба-и-отклонение).
- **STRtree** — пространственный индекс на базе R-дерева.
- **Blue noise / Poisson disk** — выборка с минимальным радиусом между точками.
- **χ²/df** — статистика хи-квадрат, нормированная на число степеней свободы.
- **Layover/shadowing** — геометрические искажения РСА из-за высот рельефа.
- **Squint** — съёмка с углом вне плоскости, перпендикулярной трассе.
- **MILP** — смешанное целочисленное линейное программирование.
- **Minkowski difference (эрозия)** — множество сдвигов, при которых фигура
  остаётся внутри области; точная область допустимых центров объекта.

### 4.4. Классическая статистика статистических испытаний (2.0.0)

`t_crit(beta, df)` — квантили распределения Стьюдента для двустороннего
доверительного интервала с надёжностью β ∈ {0.90, 0.95, 0.99} (таблица
df = 1…30, при больших df — нормальное приближение z(β); для прочих β —
оценка z). `classical_series(values, beta)` — накопленные по объёму
испытаний n оценки в терминах классической школы: статистическое
математическое ожидание M*(n) = (1/n)Σxᵢ, исправленная выборочная дисперсия
D̃(n) = Σ(xᵢ−M*)²/(n−1), оценка СКО σ̃(n) = √D̃, точность оценивания
ε(β,n) = t(β,n−1)·σ̃(n)/√n и доверительный интервал I = [M*−ε; M*+ε];
NaN исключаются, минимальный объём n = 3, данные не сглаживаются.
`required_trials(sigma, eps0, beta)` — предварительная нормальная оценка
потребного объёма n ≥ (z(β)·σ̃/ε₀)² по пилотной выборке (при малых n
уточнять по Стьюдента; не строгая гарантия для произвольного распределения;
χ²-интервалы для дисперсии не выдаются за точные без предположения
нормальности). `k_sweep(..., keep_runs=True)` возвращает на каждый K средние
G и C с доверительными полуширинами при β и сырые итоги испытаний.
`render_classical_charts` строит пять обязательных графиков: M*(n) с
границами I, D̃(n), σ̃(n), ε(β,n) с линией ε₀ (и n, где ε ≤ ε₀), G(K)/C(K)
с доверительными границами и порогами 90/95/99 %. Графики 1–4 — сходимость
статистической оценки при росте n при фиксированном K; график 5 — сходимость
алгоритма планирования при росте K при фиксированном n; это разные процессы.
Streamlit 2.6.0 — пять вкладок; криволинейное размещение доступно во вкладке
модели и исследуется наряду с четырьмя базовыми законами во вкладке статистики;
совместная модель (вкладка 5) принимает криволинейный закон объектов T,
включая импорт осевой линии из GeoJSON, и формирует геометрию
досъёмки U = T ∩ B для внешнего планирования РСА в `plane_sar` (см.
JOINT-SPATIAL-MODEL.md).
