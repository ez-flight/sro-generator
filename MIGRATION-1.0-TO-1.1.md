# Миграция 1.0 → 1.1

Версия 1.1.0 обратно совместима по конфигурациям: JSON-файлы 1.0.0 загружаются
без изменений, все поля и файлы результатов на месте. Изменились **значения
по умолчанию поведения** — перечислены ниже вместе с способами вернуть поведение 1.0.0.

## 1. Изменения поведения

### 1.1. Допустимая область центров: `exact` вместо описанного радиуса

| | 1.0.0 | 1.1.0 (по умолчанию) |
|---|---|---|
| Область центров | `inner.buffer(-R)`, R — описанный радиус формы | точная эрозия Минковского (пересечение полуплоскостей) |
| Эффект | полигон гарантированно внутри района, но свободное место недоиспользуется | больше допустимой площади, меньше ложных отказов, те же гарантии |
| Сэмплинг центров | равномерно по bbox области с отказом | равномерно внутри точной области (триангуляция) |

Вернуть поведение 1.0.0: `"placement": { ..., "center_region_mode": "legacy" }`.

### 1.2. Семантика `min_distance_m` + `allow_overlap`

В 1.0.0 положительное `min_distance_m` фактически запрещало любые перекрытия.
В 1.1.0 правила однозначны и симметричны (`pair_placement_ok`):

- полигоны не пересекаются → `distance ≥ min_distance_m`;
- пересечение по положительной площади (`area(∩) > 1e-12·min(area)`) →
  при `allow_overlap: false` запрещено; при `allow_overlap: true` допустимо,
  если `area(∩) / min(area) ≤ max_overlap_fraction`;
- касание границ (нулевая площадь пересечения) → правило расстояния:
  допустимо при `min_distance_m = 0`, отклоняется при `min_distance_m > 0`.

Для конфигураций с `allow_overlap: false` (значение по умолчанию) поведение
не изменилось. Для `allow_overlap: true, min_distance_m > 0` теперь разрешены
сценарии, которые 1.0.0 отклоняла (исправление ошибки, а не регрессия).

### 1.3. Пространственный индекс STRtree включён по умолчанию

Проверка конфликтов использует `shapely.STRtree` с периодическим перестроением.
Решения (принять/отклонить) идентичны полному перебору — подтверждено тестами
эквивалентности на параметризованных конфигурациях. Отключение:
`"placement": { ..., "spatial_index": false }`.

### 1.4. Воспроизводимость seed

Одинаковые `seed` и конфигурация внутри 1.1.0 дают одинаковый результат;
число worker параллельной серии на результат не влияет (как и в 1.0.0).
Сценарии, сгенерированные в 1.0.0, **не воспроизводятся побайтово** в 1.1.0
из-за изменения стратегии сэмплинга центров (п. 1.1). Для сравнения с записями
1.0.0 используйте `center_region_mode: "legacy"` — при `allow_overlap: false`
и `spatial_index: false` воспроизводимость полная.

## 2. Новые необязательные поля конфигурации

```json
"placement": {
  "center_region_mode": "exact",
  "spatial_index": true
}
```

Оба поля имеют значения по умолчанию; конфигурация 1.0.0 валидна без них.

## 3. Изменения в выводе

- `generation_report.json`: добавлены `version`, `placement_exact_checks_total`,
  `placement_tree_queries`, `placement_tree_rebuilds`,
  `center_region_area_mean_m2`. Существующие ключи не изменены.
- `objects_all.csv` (серия прогонов): добавлен столбец `aspect_ratio`.
- Серия прогонов: новые графики в подкаталоге `analytics/`; имена и содержимое
  четырёх исходных `chart_*.png` не изменились.
- Сводка серии: новый блок `statistical_tests` (χ² и KS с p-value и
  предупреждениями), `clark_evans_r`, `exact_checks_total`, `aspect_ratio`,
  расширенный `config`. Ключи 1.0.0 (`vertex_chi2_df` и др.) сохранены.

## 4. Миграция кода

Публичные интерфейсы не изменены:

- `generate_scenario(config)`, `export_scenario(...)`, `run_batch(...)`,
  `run_single(...)`, `summarize(...)`, `write_batch_csv(...)`,
  `render_report_charts(...)` — сигнатуры прежние;
- `place_objects(...)` получил только ключевые необязательные параметры
  `use_spatial_index` и `center_region_mode` (по умолчанию — из конфигурации);
- `PlacementReport` и `PlacedObject` расширены полями с значениями по умолчанию —
  код, создававший эти объекты, продолжает работать;
- внутренняя функция `_distance_ok` заменена документированной
  `pair_placement_ok(a, b, min_distance_m, allow_overlap, max_overlap_fraction)`
  с исправленной семантикой.

## 5. Что не изменилось

Район в WGS 84, процедурная генерация многоугольников, ручные центры, случайное
размещение, кадры-кандидаты РСА, CLI, Streamlit, экспорт GeoJSON/CSV/PNG/JSON,
параллельные серии прогонов — без изменений интерфейсов.
