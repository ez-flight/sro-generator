# CHANGELOG

## 1.2.0 — 2026-11-23

### Новый функционал

- **Исследование сходимости итерационного алгоритма формирования кадров РСА**
  (`sro_generator/convergence.py`, вкладка «Сходимость алгоритма» в Streamlit).
  Исследуемый алгоритм — рандомизированный жадный отбор кадров-кандидатов:
  на каждой итерации к объединению выбранных кадров добавляется кадр с
  максимальным приростом полноты покрытия (softmax-выбор с температурой).
- Для фиксированного сценария проводится M независимых экспериментов
  (seed подряд от начального), каждый содержит K последовательных итераций.
  Район, объекты и кадры-кандидаты между экспериментами неизменны
  (не перегенерируются) — случайность относится только к работе алгоритма;
  неизменность сценария контролируется отпечатком в каждом эксперименте.
- Полнота информации I(k) = 0.5·(покрытие района ∪ кадров + покрытие объектов
  ∪ кадров); перекрытия выбранных кадров в объединении не считаются дважды.
  Для каждого эксперимента сохраняется полная траектория I(k) с разложением
  на компоненты и списком выбранных кадров.
- По каждому номеру итерации: средняя полнота, стандартное отклонение
  (ddof=1), медиана, 10-й и 90-й процентили, 95%-й доверительный интервал
  среднего (t-критическое из встроенной таблицы Стьюдента, без scipy) и
  средний прирост полноты. Данные не сглаживаются, полоса разброса не сужается.
- Проверка гипотезы о сходимости по фактическим результатам с явной фиксацией
  случаев: «converged», «stagnation» (стабилизация ниже требуемой полноты),
  «different_local_optima» (разброс итоговых полнот выше порога),
  «no_convergence» (стабилизации нет за K итераций).
- Регулируемые параметры: M, K, начальный seed, критерий стабилизации
  (порог + скользящее окно среднего прироста), минимально требуемая полнота,
  температура алгоритма, порог разброса; эксперименты выполняются параллельно
  (результаты не зависят от числа потоков).
- Графики: средняя полнота vs k с полосой p10–p90, стандартное отклонение
  vs k, все траектории I(k) (честное отображение нестабильности), средний
  прирост vs k.
- Экспорт: `convergence_trajectories.csv`, `convergence_summary.csv`,
  `convergence_experiments.csv`, `convergence.json`, четыре PNG.

### Совместимость

- Поведение генерации сценариев не изменилось; сценарии 1.1.0
  воспроизводятся побайтово. Новые тесты: `tests/test_convergence.py` (22 шт.).

## 1.1.0 — 2026-11-22

### Исправленные ошибки

- **Размещение: конфликт `min_distance_m` с `allow_overlap/max_overlap_fraction`.**
  В 1.0.0 проверка `distance < min_distance_m` выполнялась до проверки перекрытия,
  поэтому при `min_distance_m > 0` любое пересечение (даже разрешённое
  `max_overlap_fraction`) отклонялось. Теперь правила разделены: не пересекающиеся
  полигоны должны находиться на расстоянии не менее `min_distance_m`; пересекающиеся
  по положительной площади проверяются долей `area(∩) / min(area)` против
  `max_overlap_fraction` (при `allow_overlap: true`). Касание границ без пересечения
  по площади трактуется как «не пересекаются»: при `min_distance_m = 0` допустимо,
  при `min_distance_m > 0` отклоняется. Добавлены регрессионные тесты, воспроизводящие
  исходное поведение 1.0.0.
- **Допустимая область центров через описанный радиус** (`inner.buffer(-R)`)
  существенно недоиспользовала район (например, для треугольников с большим
  описанным радиусом область могла оказаться пустой при непустой истинной).
  Реализован точный расчёт как пересечение полуплоскостей (эрозия Минковского
  выпуклой области размещения на опорную функцию формы). Поведение 1.0.0 сохранено
  в режиме `placement.center_region_mode: "legacy"`.
- **Статистика сетки 3×3** строила ожидаемые частоты по наивной равномерной
  модели ограничивающего прямоугольника. Теперь ожидаемые частоты взвешиваются
  реальной площадью пересечения ячеек с допустимой областью центров; для сложных
  гипотез доступен эталонный моделируемый вариант (`simulate_reference_quadrant_counts`).
- **χ²-статистика без p-value и без проверки применимости** — добавлены число
  степеней свободы, p-value (регуляризованная неполная гамма-функция, без новых
  зависимостей) и предупреждения при малых ожидаемых частотах (правило Кохрана).
- **Нумерация/учёт**: `PlacementReport` пополняется счётчиками точных проверок пар,
  запросов и перестроений STRtree, средней площадью допустимой области и долями
  ячеек сетки — всё с значениями по умолчанию (обратная совместимость dataclass).

### Новые алгоритмы

- **Точная область допустимых центров** (`exact_center_region`): для выпуклой
  области размещения (все прямоугольные районы, в том числе повёрнутые) область
  `{t : form + t ⊆ inner}` вычисляется точно как пересечение полуплоскостей
  `n·t ≤ c − max(n·v)` по рёбрам области; поддерживает невыпуклые формы объектов
  (максимум линейной функции по контуру). Невыпуклая область → автоматический
  откат на legacy-режим с предупреждением. Равномерный сэмплинг внутри области —
  веерная триангуляция от центроида.
- **Пространственный индекс STRtree** для проверки конфликтов: неизменяемый индекс
  Shapely 2.x перестраивается каждые 64 новых объекта; объекты, добавленные после
  перестроения, проверяются линейно по ограничивающим прямоугольникам. Запрос —
  bbox кандидата, расширенный на `min_distance_m`; точная проверка пар неизменна,
  поэтому решения STRtree и полного перебора совпадают (подтверждено тестами
  и бенчмарком). Отключение: `placement.spatial_index: false`.
- **Статистическая верификация**: критерий χ² Пирсона с p-value и проверкой
  применимости (число вершин, категории, приоритет, сроки, разрешения, сетка 3×3);
  критерий Колмогорова–Смирнова для непрерывных площадей и углов поворота
  (с защитой от применения к дискретным распределениям и предупреждениями для
  малых выборок); индекс Кларка–Эванса по NND (как описательная метрика).

### Новые графики

Сохранены четыре исходных PNG (`chart_placement/attributes/geometry/frames_space.png`).
Добавлены (подкаталог `analytics/`): распределение площадей, числа вершин,
отношения сторон, углов поворота, NND, сетка 3×3, тепловая карта центров,
попытки vs заполнение, доля успешных прогонов, сводка χ²/p-value, сравнение серий,
а также графики бенчмарка (время/проверки/память vs число объектов).
Реальные измерения, теоретические ожидания и результаты моделирования различаются
цветом и подписями.

### Интерфейс

- `placement.center_region_mode: "exact" | "legacy"` (по умолчанию `"exact"`);
- `placement.spatial_index: bool` (по умолчанию `true`);
- JSON-конфигурации 1.0.0 валидны без изменений (новые поля имеют значения
  по умолчанию);
- `stats.py`: новые функции `chi2_gof`, `ks_test`, `chi2_sf`, `kolmogorov_sf`,
  `clark_evans_index`, `simulate_reference_quadrant_counts`,
  `render_analytics_charts`, `render_series_comparison`, `render_benchmark_charts`;
  `run_batch` принимает `reference_quadrant_counts`;
- Streamlit: новая вкладка «Аналитика» (статистические тесты + новые графики);
- `generation_report.json` дополнен версией и счётчиками размещения.

### Совместимость и воспроизводимость

- Одинаковый `seed` внутри версии 1.1.0 даёт побайтово одинаковый результат;
  число worker не влияет на случайные результаты серии.
- Сценарии 1.0.0 **не воспроизводятся побайтово**: изменилась стратегия сэмплинга
  центров (равномерный в точной области вместо rejection sampling по bbox
  буферизованной области). Режим `legacy` повторяет поведение 1.0.0, но
  исправленная семантика пересечений всё равно может менять результаты сценариев
  с `allow_overlap: true` и `min_distance_m > 0`. Подробности — в
  MIGRATION-1.0-TO-1.1.md.
